Best config to run each model, by context regime — Apple Silicon (M-series), greedy temp=0.

updated 2026-06-15 · branch perf/inference-optimization

The winning configuration flips with context length. At short context the KV read is cheap, so speculative decoding wins (more tokens per target forward). At long context the growing global-attention KV read dominates each step, so kvflash bounded residency wins — and host-paging + reranker drafter adds mid-context recall at the same bounded read.

⚠️ The short-context spec ratios are inherited from the 2026-06-12 same-session bench and are cold-biased (AR measured first / cold MoE-gather JIT; spec measured warm) — a warm 35B re-bench flipped DFlash from 1.40× to 0.95×. Trust the AR decode numbers; treat spec ratios as needs warm re-bench unless marked ✓warm. The long-context kvflash numbers were each measured warm, in-process.

Recommendations

⚡ Fast daily driver (short prompts)

gemma4-e4b (60.8) or the 35B-A3B MoE (~70 warm AR) — run the 35B plain AR; spec doesn't help it warm.

📚 Long-document / RAG / large context

Add DFLASH_KVFLASH=<pool> (+ DFLASH_KVFLASH_PAGING=1 DFLASH_KVFLASH_DRAFTER=1 for mid-context recall) — best throughput past ~8K and the only config that recalls an evicted fact at a bounded KV read.

🚀 Biggest spec win (short ctx)

Gemma4-27B-MTPLX pair (2.04×) — pending a warm re-bench to confirm the ratio.

🛟 Safe default

kvflash is byte-identical to the default cache on short prompts (nothing evicted), so it's safe to leave on for long-context workloads.
